# 自动化执行能力规范

qalore 的「自动化」不是独立 capability，而是 qa-execution 的一种**触发模式**。本文件声明自动化执行能力的不变式；触发方式（DSH 定时 / cron / CI / Hook）由宿主环境提供，qalore 不写死。

> 机器可判定不变式见 `contracts.json#automation`，本文件为语义权威。

---

## 能力定义

自动化 = 宿主环境触发「自动化入口」，执行已沉淀的 TC 断言（前端 UI/样式 + 接口 + DB），产出可拉取的报告。触发源是宿主环境的职责，不是 qalore 的职责。

## 五条不变式（spec 边界，非 case-by-case 步骤）

| 不变式 | 声明 | 为什么是边界 |
|--------|------|------------|
| 幂等 | 每次执行独立；跑前环境干净或只读 | 定时重跑不累积脏状态 |
| 只读安全 | 无人值守 = 无实时人类确认 → 只跑 `read-verify` 无副作用用例；含写 mock 的用例自动 SKIP | 权限左移「确认」环节在无人值守下无法实时发生 |
| 失败可见 | 报告落盘到固定路径，可被宿主/用户拉取 | 不静默失败 |
| 漂移保护 | 同一 TC 连续 FAIL ≥ 3 次 → 标记「疑似断言漂移」→ 进回写清单 | 不永远红灯无人管 |
| 范围声明 | 触发时携带「模块/优先级」范围，机器校验声明与执行一致 | 不失控全量 |

## 触发源抽象

qa-execution 提供「自动化入口」：接收 `{执行范围}`（模块/优先级）→ 跑 → 落盘报告。宿主环境（DSH schedule / cron / CI / Claude Code Hook / Codex / WorkBuddy）各自用本环境机制触发该入口，qalore 不规定触发器。

## 与验证/校准模式的关系

自动化模式默认只跑「高置信度 + 已确认」的用例（验证模式）。低置信度断言（校准模式）在无人值守下只做「校准采集」不判 FAIL，避免「推理假设未对齐」被误判为红灯。
