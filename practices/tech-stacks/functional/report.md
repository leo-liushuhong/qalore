# 测试报告规范

qa-report 的报告产出标准：报告字段契约、四权威来源、测试结果可信度标准、结论判定标准、机器重算规则、标准报告模板、模板适配规则。

> 章节导航：报告层级区分 · 四权威来源 · 报告字段契约（唯一权威来源）· 测试结果可信度标准 · 结论判定标准 · 机器重算规则 · 标准报告模板 · 模板适配规则 · 数据来源追踪表

---

## 报告层级区分

| 层级 | 产出方 | 粒度 | 落点 |
|------|--------|------|------|
| 执行报告 | qa-execution | 模块级 | story 执行报告文件（`{模块}-功能-执行报告.md`，供审计追溯）|
| 测试报告 | qa-report | 需求级 | 可交付文件（workspace/下载，供用户交付）|

两者不混用：执行报告是 story 资产（持久化、供审计追溯），测试报告是交付物（一次性产出、供用户评审）。测试报告**不落 story**，其审计追溯靠「执行报告 + defects 段 + data_fixtures.instances」三者，不新增需求级汇总文件。

---

## 四权威来源

测试报告的每个字段必须来自以下四个权威来源之一，**禁止现编数据**：

| 来源 | 内容 | 权威位置 |
|------|------|---------|
| 执行结果 | PASS/FAIL/SKIP 计数、通过率 | story 执行报告文件 / 对话内执行结果 |
| 缺陷数据 | 外部缺陷系统登记的缺陷 | story `dependencies.json` 的 `defects` 段 + 外部缺陷系统 |
| 验收数据 | 造数结果指纹 | story `dependencies.json` 的 `data_fixtures.instances` |
| 需求边界 | 功能点覆盖 + 回归候选 | story 业务逻辑.md + index.json `business_related`/`depends_on` |

---

## 报告字段契约（唯一权威来源）

> 每个字段绑定唯一权威来源；缺失来源标「待补充」，**绝不猜测**。

| 报告字段 | 权威来源 | 缺失时行为 |
|---------|---------|-----------|
| 测试结论 | 执行结果汇总（通过率 + 遗留风险）| 机器重算，不手写 |
| 风险与建议 | 未实现项 + 规避措施（业务逻辑.md 的「暂不实现」标记）| 列出未实现清单，不猜测 |
| 版本质量 | 缺陷统计（外部缺陷系统真实状态/优先级/严重度）| 标「待拉取缺陷系统」|
| 测试目标 | 需求边界（功能点覆盖）+ 回归候选（`business_related`/`depends_on`）| 从 story 聚合 |
| 文档链接 | `dependencies.json` 的 `inputs` + 用户提供 | 标「待补充」|
| 缺陷统计 | `defects` 段 + 外部缺陷系统（**绝不猜优先级/严重度/状态**）| 标「待拉取」|
| 执行用例/通过率 | 执行报告机器重算 | 机器算，不手算 |
| 关键验收数据 | `data_fixtures.instances.fingerprint` | 标「无验收数据」|
| 测试负责人 | 外部缺陷系统当前用户 | 自动取当前用户 |

## 测试结果可信度标准

测试报告的每个结果必须绑定证据链，无证据不落笔（哲学19：可信度来自可追溯的证据，非 AI 判断）。

### 结果四态与证据链

| 结果 | 定义 | 证据链（缺一不可） |
|------|------|------------------|
| PASS | 断言实测值符合预期值 | 实测证据（API 响应体 / trace 报文 / DB 记录 / 截图）+ 断言预期值 |
| FAIL | 断言实测值不符合预期 | 实测证据（实测值）+ 预期值 + 缺陷单（外部缺陷系统真实登记） |
| 本期不做 | 产品确认不覆盖 | 产品确认记录（业务逻辑「本期不做」标记） |
| 待确认 | 无法判定 | 实测证据 + 待确认原因 |

### 可信度判据

一个结果要可信，必须同时满足：
1. **可追溯**：能定位到具体 TC / 断言 / 实测动作（不写「大概」「应该」）
2. **有证据**：实测值有来源（响应体 / trace / DB / 截图），非 AI 记忆
3. **有对比**：PASS/FAIL 必须写「预期值 vs 实测值」，禁止只写「正常」「通过」而无对比值

## 结论判定标准

测试结论由机器重算，不手写、不拍脑袋：

| 条件 | 结论 |
|------|------|
| 通过率 ≥ 通过门槛 且 遗留缺陷 = 0 | 验证通过 |
| 通过率 ≥ 通过门槛 但 遗留缺陷 > 0 | 基本通过 |
| 通过率 < 通过门槛 | 不通过 |

术语定义：
- **通过门槛**：核心功能通过率下限（默认 95%；公司如有特定标准，可在公司级 spec 覆盖，公共层只定义机制）
- **遗留缺陷**：状态为「待确认 / 待修复 / 重新打开」的缺陷（「已关闭」不计）
- **通过率**：见「机器重算规则」

---

## 机器重算规则

- 通过率 = PASS / (PASS + FAIL) × 100%（**SKIP 与「本期不做」不参与分母**；「本期不做」是 SKIP 的一种语义——产品确认不覆盖）
- 缺陷统计 = `defects` 段登记条目（从外部缺陷系统拉取真实状态）
- 用例数 = 执行报告统计（对齐 `contracts.json#counting_formulas`）
- 验收数据 = `data_fixtures.instances` 指纹

## 标准报告模板

无外部模板（xlsx/docx）或模板无法识别时，qa-report 按以下标准模板产出（markdown）。每章字段绑定权威来源（见「报告字段契约」），机器重算字段（通过率/缺陷统计/用例数）不手写。

### 结构说明表（每章排版类型）

| 章 | 排版结构 |
|----|---------|
| 一 测试结论 | 段落 + 2 列表格（项/内容，2 行：通过标准/结论） |
| 二 风险与建议 | 3 列表格（风险/影响/规避措施），每行一条未实现项 |
| 三 版本质量 | 纯段落（综合评价 + 缺陷分布 + 核心链路闭环描述） |
| 四 基本信息 | 2 列表格（项/内容）+ 3 列表格（角色/负责人/文档） |
| 五 测试目标 | 无序列表（覆盖点）+ 1 段「边界说明」 |
| 六 测试范围 | 3 列表格（产品线/模块/功能点） |
| 七 测试环境 | 2 列表格（项/内容） |
| 八 测试结果 | 「用例总数」段 + 3 列表格（状态/数量/说明）+「通过率」段 + 2 列表格（功能点/实测结果） |
| 九 缺陷统计 | 5 列表格（ID/标题/优先级/状态/负责人）+「缺陷分布」段 |
| 十 关键验收数据 | 2 列表格（核心功能点/验收数据） |

### 完整模板（占位符约定：`{...}` 必填、`{A/B/C}` 枚举选择、`{x/(x+y)×100}%` 机器重算）

```markdown

| 项 | 内容 |

## 五、测试目标

- {覆盖点2}
- {覆盖点3}

## 九、缺陷统计

| ID | 标题 | 优先级 | 状态 | 负责人 |
|----|------|--------|------|--------|
| {缺陷链接} | {缺陷标题} | {优先级} | {状态} | {负责人} |

缺陷分布：总计 {N} 个，{M} 个已关闭、{K} 个遗留（待确认/待修复/重新打开）；优先级「高」×{a}、「中」×{b}、「低」×{c}。

## 十、关键验收数据

| 核心功能点 | 验收数据 |
```

## 模板适配规则

- 报告模板由用户提供（xlsx/docx），通过 office 套件读取
- **按字段标题匹配，不按固定 cell 坐标**（模板列位置可变化）
- 模板结构无法识别 → 回退「标准报告模板」（见上节），或询问用户
