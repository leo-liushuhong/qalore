## 核心思考哲学：报告 = 四权威来源聚合，不是重新创作

每个报告字段绑定唯一权威来源，AI 只做「聚合 + 格式化 + 机器重算」，
缺失来源标「待补充」，**绝不现编数据**。

四权威来源与字段契约见 `{practices_path}/tech-stacks/functional/report.md`（唯一权威来源）。

## 触发条件

## 执行流程

```
1. 读取报告模板（xlsx/docx，office 套件）→ 识别模板字段结构（sheet/行/cell）；无外部模板 → 用 report.md「标准报告模板」
2. 聚合四权威来源 → 产出「报告数据模型」（字段 → 值 → 来源）
3. 机器重算：通过率 / 缺陷统计 / 用例数 / 验收数据（规则见 report.md「机器重算规则」）
4. 结论判定：按 report.md「结论判定标准」机器判定（验证通过/基本通过/不通过），不手写
5. 可信度校验：每个结果绑定证据链（见 report.md「测试结果可信度标准」），无证据标「待补充」
6. 字段 ↔ 模板 cell 映射（按字段标题匹配，不按固定坐标），填充
7. 输出报告文件 + 「数据来源追踪表」（每个字段从哪个来源取）
```

---

## 约束

- **不现编数据**：字段无权威来源 → 标「待补充」，不填猜测值
- **缺陷数据只从 defects 段 + 外部缺陷系统拉**，不手写优先级/严重度/状态
- **模板适配**：先读模板结构再填充，不假设模板布局
- **结论不手写**：按「结论判定标准」机器判定，禁止拍脑袋
- **结果可信度**：PASS/FAIL/本期不做/待确认 四态，每态绑定证据链（无证据不落笔）
